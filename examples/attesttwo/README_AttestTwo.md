# AttestTwo

AttestTwo is a demonstration of how to generate and verify enclave attestation reports using Keystone. It consists of two enclaves: Target and Attestor, along with a host application that facilitates communication and verifies the attestation results :

1. **Target Enclave (`attesttwo_target`)**  
   A minimal enclave whose sole purpose is to exist as an ELF on disk. It returns immediately when launched; its binary is later measured by the Security Monitor (SM).

2. **Attestor Enclave (`attesttwo_attestor`)**  
   An enclave that:
   - Requests a 16-hex-digit nonce from the host.
   - Requests the path of the target enclave from the host.
   - Derives two “checkpoint” values (in [1..10000]) from the nonce and prints them via OCALLs.
   - Calls `attest_enclave()` to have the SM measure and sign the target enclave’s ELF.
   - Returns the 4096-byte signed attestation report to the host via an OCALL.

3. **Host Runner (`attesttwo_runner`)**  
   A host-side program that:
   - Launches the target enclave to verify it loads successfully.
   - Launches the attestor enclave, handles its OCALLs (get nonce, get target path, print checkpoints, copy report), and invokes the SM when `attest_enclave()` is called.
   - Receives the 4096-byte report, verifies its signature, and prints out the embedded nonce.

## Building inside keystone

Run the following to clean the  buildroot:

```bash
make BUILDROOT_TARGET=keystone-examples-dirclean
```
then run :

```bash 
make -j$(nproc)
```

## Running in QEMU

1. In QEMU’s root shell:
   ```bash
   # modprobe keystone-driver
   # /usr/share/keystone/examples/attesttwo.ke
   ```
2. Expected output:

   ```
   Verifying archive integrity... MD5 checksums are OK. All good.
   Uncompressing Keystone Enclave Package

   1) Launching Target Enclave (just to confirm it loads)...
      --> Target enclave returned immediately.

   2) Launching Attestor Enclave (will produce report for Target)...
   [Attestor] value: 2254
   [Attestor] value: 4390
      --> Attestor enclave returned. Report length = 4096 bytes.

   *** Attestation report signature is VALID. ***
   Nonce in report: 3c1eff453e248aed (length=17)
   ```
Note: Each execution generates a new random nonce, resulting in different checkpoint values and a fresh attestation report each time.

## Some Points to be noticed on this project :

- **No standard C library inside enclaves**  
  All functions (`strlen`, `memset`, hex parsing) are implemented manually. Only Keystone headers (`app/eapp_utils.h`, `app/syscall.h`, `edge/edge_common.h`) are used for OCALL and shared-buffer operations.

- **External attestation**  
 This example demonstrates remote attestation of a separate enclave binary.
 The Attestor enclave requests the SM (via the host) to hash and sign the target ELF, embedding a fresh nonce.
 The resulting 4096-byte signed report is returned to the Attestor, then forwarded to the host for verification.

- **Nonce-based freshness**  
  A fresh 16-hex nonce is generated by the host for each attestation run.  
  The SM includes this nonce in the signed report, ensuring that the report cannot be replayed.

- **SHA3 hashing**  
  Keystone’s SM uses SHA3 to compute the measurement of the target ELF before signing. This ensures a cryptographic “fingerprint” of the target binary.
